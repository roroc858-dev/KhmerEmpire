# Deployment guide

## Render Blueprint

The repository root contains `render.yaml`. In Render, create a Blueprint from the GitHub repository and select the `main` branch. The Blueprint creates the Next.js web service in Singapore, builds from the monorepo root, applies Prisma migrations during the build, and checks `/api/health`.

The initial service plan is `free` to avoid enabling paid compute unexpectedly. Free services may spin down when idle and are not suitable for reliable production checkout or delivery. Select a paid plan in Render when you are ready for production traffic. Render only supports pre-deploy commands on paid web services; on this free starter configuration, migrations run in the build command. For production, move `npm run db:migrate` to `preDeployCommand` after selecting a paid plan, so migrations run immediately before the service deploys.

During initial Blueprint setup, Render prompts for variables marked `sync: false`. Set them in the Render Dashboard, not in `render.yaml` or source control.

## Supabase connection

1. Create a Supabase project and open **Connect** in its Dashboard.
2. Set `DATABASE_URL` to the Supabase transaction-pooler connection string (port `6543`) and append `?pgbouncer=true` if the copied URL has no query string. Prisma uses this for application queries.
3. Set `DIRECT_URL` to the direct connection string (port `5432`) for migrations. If Render cannot reach the project's direct IPv6 endpoint, use Supabase's session-pooler connection string (port `5432`) instead. Do not use the transaction pooler for migrations.
4. Keep TLS enabled (`sslmode=require`) and URL-encode reserved characters in the database password.
5. Set the Supabase URL, anon key, and service-role key in Render. The service-role key is a backend secret and must never be exposed to browser code.

Prisma's `DATABASE_URL` is the runtime connection; `DIRECT_URL` is used by Prisma Migrate. The generated Prisma client is included in the Render build, and `/api/health` returns `503` until it can execute a database query.

## Required Render variables

- `DATABASE_URL` — Supabase transaction pooler URL for Prisma runtime.
- `DIRECT_URL` — Supabase direct or session-pooler URL for migrations.
- `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` — browser-safe Supabase configuration.
- `SUPABASE_SERVICE_ROLE_KEY` — server-only secret.
- `APP_URL`, `ADMIN_EMAILS`, and `MANUAL_PAYMENT_INSTRUCTIONS` — application settings.
- `AUTH_SECRET` and `SERVER_CREDENTIAL_ENCRYPTION_KEY` — generated by Render in the Blueprint.

See `.env.example` for the complete variable list. `npm run db:migrate` applies checked-in Prisma migrations; do not use `db push` for production.

## Production checklist

- Confirm Supabase backups and recovery access.
- Confirm Render variables are configured and `/api/health` reports `database: connected`.
- Replace the free Render plan for production traffic.
- Verify administrative authorization and payment review before accepting orders.
- Rotate server credentials and store them outside source control.
